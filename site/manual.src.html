Before you start

What you need

  • A Push 3 Standalone with Push Hack: push-manager, push-display and push-catalog, version 0.2.0-alpha or newer. That release brings the Live device extensions Pung is built on.
  • Push Hack's VST3 scan switched on: Push Manager, System tab.
  • The PushHack Remote Script in Live: Live's Settings › MIDI › Control Surface: PushHack. The Pung view follows Live's selection through it.
Which Push Hack

Pung needs Push Hack's Live device extensions (the vision page lists them). They are part of Push Hack since 0.2.0-alpha. With an older Push Hack, Pung's view does not open in place of Push's device view, and the pads do not stay with Live while it is open.

Setup

Install

Pung is in Push Hack Catalog. Install it there like any other hack.

  1. Open Push Hack Catalog in a browser on your computer or phone.

    In your browser
    http://push.local:7702

  2. Find Pung and choose Install. The Catalog downloads pung.tar.gz (151 MB, every module inside), installs the service and starts it.

  3. Restart the Push once. Live looks for new plugins only when it starts. After the restart, Pung's devices are in Push's browser and Pung is in Push Hack Home (Shift + Help).

Later versions arrive the same way; see Updating.

Setup

Updating

An update has two parts: Pung itself, then the modules you installed. Both are done in a browser; nothing is copied by hand.

  1. Update Pung. Open Push Hack Catalog (http://push.local:7702), find Pung and choose Update. Your installed modules, their firmware, your sounds and your favourites are kept: they are stored apart from the program. Devices in an open Set keep their state.

  2. Update your modules. Open Pung's web page (http://push.local:7720) and go to Modules; the tab shows how many updates there are. Press Update on each module that offers one.

  3. Apply. Save your Set first. Apply restarts Live once, in about 30 seconds, and Live recovers the Set.

  • Update to 1.2.3 means the module's author released a new version.
  • Update (new build) means the version is the same, but Pung packed it again, usually because the first package left something out. The update to Pung 0.1.17 did this for twelve modules: Surge XT got its 674 factory patches, Helm its presets, Dexed its banks and Breakbeat its loops.
  • Module updates only show after step 1: the new list of modules comes with Pung.
  • The modules that come built into Pung (Braids, Dexed, Hera, OB-Xd) are updated by step 1 alone.

Getting started

Your first Pung device

  1. Select a MIDI track and open Push's browser to add an instrument.

  2. Open User Library › Presets. Pung's devices are in Instruments › Pung (synths), Audio Effects › Pung (effects) and Instruments › Pung MIDI Effects (MIDI effects on a track of their own). Each entry also carries Live's own tags, such as Synthesizer › FM for Dexed or Reverb for CloudSeed, for browsers that filter by tag.

  3. Load one. With Push in its device view, the Pung view opens by itself. Play the pads: scales, layouts, Note Repeat and recording are Live's, as always.

Pung devices are ordinary Live devices. Put them in racks, automate them, send to them, save the Set: Live keeps every module's state with the Set. The modules run outside Live's process, so if one crashes, Live goes on and the device is silent until Pung has restarted it.

On the Push

Sounds

Every Pung device's sounds are browsed the same way, whichever module it runs: its own sounds (Factory), the ones you saved (User), your Favourites and what you chose lately (Recent). Open the device, then press SOUNDS (upper button 8) or the jog wheel. The browser works like Push's own.

Jog wheel, pressOne level down. On a sound: keep it and close the browser.
Jog wheel, nudge leftOne level back up.
Jog wheel, nudge rightOn a sound, its menu: favourite, Save, Save As, Rename, Delete (which asks first).
Upper rowStraight to Factory, User, Favourites or Recent.

  • Nothing is lost by looking. Cancel, or leaving the browser any way but loading, brings back the sound you had, exactly.
  • Naming: Save As proposes a name. To change it, turn the jog wheel for the letter at the cursor and nudge it to move the cursor, or turn the eight encoders, one letter each. Press the jog wheel when done.
  • Your sounds are Schwung's own user presets, file for file: a sound saved on Move opens on Push, and the other way round.
  • Your sounds are in Push's own browser too: User Library › Presets › Instruments › Pung › Mini-JV › your sound (and the same for every module). Loading one brings the module with that sound, already named.
  • Every sound has its name from the start. Where a module can only name the sound it has loaded, Pung reads the other names in the background the first time, without changing your device's sound; that takes a few seconds, once per module and bank.
  • The Pung view's header names the device's sound; a * in front means you changed it since.

On the Push

Pages and screens

A module's pages come from the module itself: its own sections and their names, in its order. Every parameter is on a page, and each device remembers the page you left it on.

Where a page holds something Pung recognises, it draws it as a picture over the encoders that set it, with each encoder's name and value below. Touch an encoder and its part of the picture lights up.

  • An envelope: its stages as one shape, whatever the module calls them (attack, decay, sustain and release; or a JV's T1 to T4, a DX7's R1 to R4).
  • A filter: its response curve from cutoff, resonance and type (low-pass, high-pass, band-pass or notch, and how steep).
  • An LFO: its wave, with more cycles the faster its rate.
  • A mix of sources: a fader over each level, and how much each source contributes to the whole.

Nodal Red 2X: a whole front panel

Nodal Red 2X emulates the Clavia Nord Lead 2X. It is the first module written for the Push alone: it runs two emulated signal processors, more than a Move could. Its first page is the instrument's front panel in its red. Every knob stands where the sound has it, so you read a sound as you would on the hardware, and the eight encoders play what a hand reaches for first: the slot, cutoff, resonance, envelope amount, mix, attack, release and portamento.

[[screen img="nord_panel" title="Nodal Red 2X: the panel" alt="Nodal Red 2X's Panel screen: a red front panel with the sections Slot, LFO 1, Mod Env, Oscillators, Amplifier and Filter, each knob drawn at its value, lit legends for the selectors, and the eight encoders' names and values on a dark red row below." up="0" upsel="0" lo="0-4" losel="0"]]The whole screen is the instrument. A Push 3 capture.[[/screen]]

The Nord is played by its four slots. Edit Slot picks the slot the knobs edit, and Slot A to D switch slots into the layer; the letters A B C D at the top right of every screen show which are layered and which one you are editing. A sound from SOUNDS loads into the edited slot; a performance replaces all four.

Its other pages follow the panel's sections: both oscillators as waveforms, the filter with its envelope, the amplifier, and who modulates what. Morph is the Nord's own idea: velocity or the mod wheel moves many knobs at once, each by its own range. On the Morph pages every range is drawn on its knob: the line is where the knob stands, the arc is where full morph takes it.

[[screen img="nord_mod" title="Who moves what" alt="Nodal Red 2X's Modulation screen: LFO 1, LFO 2, the mod envelope and the wheel on the left, their destinations on the right, joined by lines as thick as each amount." up="0" upsel="0" lo="0-4" losel="1"]]LFO 1 on the filter, the mod envelope on FM, the wheel on morph: each line is as thick as its amount.[[/screen]] [[screen img="nord_morph" title="Morph, on the knobs" alt="Nodal Red 2X's Morph Filter page: seven dials for cutoff, resonance, envelope amount and the filter envelope's stages, each with a line at its value and a coloured arc to where full morph moves it." up="0" upsel="0" lo="0-4" losel="5"]]The filter's morph ranges. Turn an encoder to set how far velocity or the wheel takes that knob.[[/screen]]

Firmware and sounds. The module needs a Nord Lead 2X firmware file, which Pung never ships; add it on the module's card. On its first start it reads the 890 sounds stored inside that firmware and keeps them as banks. That takes about three minutes, once, and the sound stutters while it runs. The Nord stores no names: a bank file's sounds can be named by a text file of the same name beside it, one name a line. Sound banks of your own (.syx) go into the module's Banks folder.

One at a time. The emulator needs most of a Push's processor. A second Nodal Red 2X in a Set stays silent and says it is waiting; it starts when the first one is removed.

OsTIrus: the Virus TI, Soft Knobs first

OsTIrus emulates the Access Virus TI, and with it the TI2 and the Snow. A Virus sound is played from three knobs its sound designer named: the Soft Knobs. Every factory sound points them at what matters in it and calls them so (Vibrato, Thinner, Infect). So the device opens on a front panel whose first three encoders are those knobs, under the sound's own names, beside the five every Virus player reaches for: cutoff, resonance, filter envelope, and the delay and reverb sends. Above them, the display (bank, sound, category) and what the sound is made of: its oscillator models, its filters and how they are wired, which effects are on.

[[screen img="osti_panel" title="OsTIrus: the front panel" alt="OsTIrus's front panel: a Virus-style display reading TI Rom A 006, BelisimoBC, Pad, with the Soft Knobs Vibrato, Thinner and Infect; panels for the oscillators (HyperSaw, Wavetable), the filters (low pass into high pass, Serial 4) and the effects (Delay on); the eight encoders' names and values below." up="0-7" upsel="0" lo="0" losel="0"]]The sound's three Soft Knobs on the first three encoders, under its own names. A Push 3 capture.[[/screen]]

The other pages follow the synth's sections, eight knobs a page, and the same knob does the same job on sibling pages: attack is knob 1 of every envelope, rate knob 1 of every LFO. Each page has a picture of what its knobs do together: the oscillators as waves, the two filters as the signal path they form, the envelopes and LFOs as shapes, every effect as a row of bars. The modulation matrix has a page for each of its six slots, a source and three destinations, each line as thick as its amount; a destination with no amount is drawn as off.

[[screen img="osti_filters" title="Two filters, as they are wired" alt="OsTIrus's Filters page: the responses of filter 1 and filter 2 side by side, the routing Serial 4, the balance, saturation and cutoff link at the right, the eight encoders' names and values below." up="0-7" upsel="2" lo="0-7" losel="5"]]Filter 1 and filter 2 as the sound passes them, and how they are routed.[[/screen]] [[screen img="osti_matrix" title="A matrix slot" alt="OsTIrus's Matrix Slot 1 page: LFO 2 Bipolar on the left, joined to Osc Balance, Osc 2 Wavetable Index and Osc Volume on the right by lines as thick as each amount." up="0-7" upsel="6" lo="0-7" losel="6"]]One source, three destinations, each line as strong as its amount.[[/screen]]

Firmware and sounds. OsTIrus needs the Virus TI firmware: the .bin file that comes with Access's Virus TI installer. Pung never ships it; add it on the module's card, and Pung recognises it by its size, whatever the file is called. The firmware holds the factory banks of all three synths, named as on the hardware: TI Rom A to S, TI2 Rom A to Y and Snow Rom A to H. Every model plays every bank.

TI, TI2 or Snow. The model is on the Synth page. Switching it restarts the emulator for a moment and keeps the sound you are editing, so you can hear one sound on another Virus.

In Live. Live keeps 128 of OsTIrus's 234 parameters for automation and Push's own device view: the front panel, the oscillators, filters, envelopes and effects. The LFOs, the matrix, the arpeggiator and the voice settings are edited in the Pung view.

One at a time. As with Nodal Red 2X, the emulator needs most of a Push's processor. A second OsTIrus in a Set stays silent, and its screens say Waiting; it starts when the first one is removed.

Vavra: the microQ, edited through its matrix

Vavra emulates the Waldorf microQ. The microQ is edited through a matrix: seven lit rows (Oscillators, Mixer, Filters, Amp/FX, Envelopes, LFOs and Mod Matrix), each printing what its knobs do. Vavra opens on that matrix, in the microQ's charcoal and amber, beside its green two-line display. The lower buttons light a row, and the eight encoders are that row's eight parameters.

[[screen img="vavra_panel" title="Vavra: the edit matrix" alt="Vavra's front panel: a green dot-matrix display reading OBX Purple5 PROX and A006 Lead OSC, beside the microQ's matrix of seven amber rows with the Oscillators row lit; below, the eight encoders' names and values, and the rows' names over the lower buttons." up="0-7" upsel="0" lo="0-6" losel="0"]]The Oscillators row lit: the encoders are both oscillators' shape, octave, semitone and detune. Rendered by Pung from a running Vavra.[[/screen]]

Every section also has pages of its own, each with a picture: the three oscillators as waves, the mixer as faders between the two filters, the filters as their curves and how they are wired, the four five-stage envelopes, the three LFOs, the modulation matrix (eight fast slots, eight standard slots and four modifiers), and the arpeggiator with its sixteen-step user pattern.

Effects. The microQ has two effect slots, and what an effect knob does depends on the effect in its slot. The effects panel names its knobs after the effect it holds. Choose Phaser, and the knobs read Speed, Depth, Feedback, Center, Spacing and Polarity. In Live the same knobs are called FX1 Param 1 to 14, because Live keeps a parameter's name fixed.

[[screen img="vavra_fx" title="The effects name their own knobs" alt="Vavra's effects panel: the display reads FX 1 Phaser; FX 1 Phaser and FX 2 Reverb as two lit boxes; the encoders read Type, Mix, Speed, Depth, Feedback, Center, Spacing and Polarity." up="0-7" upsel="5" lo="0-3" losel="0"]]FX 1 holds a Phaser, so its knobs are the Phaser's.[[/screen]]

Firmware and sounds. Vavra needs the microQ's operating system: the update file mq_2_23.mid from Waldorf, or a 512 KB dump of a microQ's ROM. Add it on the module's card. An operating system carries no sounds, because a microQ keeps them in its own memory. Add a sound set on the card's Sounds row: Waldorf's factory set is mQ_factory2001.mid, in the microQ 2.22 update package, with 300 sounds in banks A to C. Every set you add there becomes more banks.

In Live. Live keeps 97 of Vavra's 341 parameters for automation and Push's own device view: the matrix's seven rows (filter cutoff, resonance and envelope, both main envelopes, the LFOs and the effects' types and mix among them), the oscillators and the mixer. The rest, the filters' and envelopes' further settings, the effects' own knobs, the modulation slots and the arpeggiator, is edited in the Pung view.

One at a time. A second Vavra in a Set stays silent, and its screens say Waiting; it starts when the first one is removed.

Xenia: the Microwave II/XT and its wavetables

Xenia emulates the Waldorf Microwave II and XT. A Microwave sound is a path through a wavetable: 64 wave positions, each oscillator starting at one of them, the envelopes moving it along. Xenia opens on that table, drawn from the real waves the synth holds, beside the XT's two-line display in its orange. The two oscillators' start positions are lit in the table; the encoders are the panel's knobs: the wavetable, both start waves, the wave envelope's amount, the filter and the volume.

A table changes as you turn the Wavetable knob, and Xenia reads the new one from the synth (about a second for its waves to arrive). Some tables are not stored as waves: the synth computes them as it plays, and the panel names them rather than drawing them. A start wave of 61 to 63 is one of the three fixed waves at the end of every table, lit beside it.

Every section has pages of its own, each with a picture: the two oscillators on a ruler of octaves, the table again with how far the keys move each start, the mixer with the Microwave's aliasing, quantising and clipping, the two filters as curves, the two LFOs, the wave envelope's eight stages as the path through the table with its key-on and key-off loops, the sixteen modulation slots and four modifiers, and the arpeggiator's sixteen-step pattern. The filter, amp and free envelopes are Pung's own envelope.

The effect. What the effect's knobs A, B and C do depends on the effect. The effect panel names them after it: choose Delay, and they read Time, Feedback and Mix.

Firmware. Xenia needs a Microwave II/XT ROM: a 256 KB dump, or its two 128 KB halves (the Am29F010 chips). An operating system update file alone is not enough, because the ROM holds the wavetables and the sounds; beside a ROM, an update file (mw2_xt_xtk_sys_v233.mid) updates it. Add the files on the module's card. The 256 factory sounds are in banks A and B.

In Live. Live keeps 119 of Xenia's 214 parameters for automation and Push's own device view: the front panel, the oscillators, the waves and the mixer, the filters, all four envelopes, the LFOs, the effect and glide, and the voice settings. The play parameters, the modulation matrix and the arpeggiator are edited in the Pung view.

One at a time. A second Xenia in a Set stays silent, and its screens say Waiting; it starts when the first one is removed.

Vivace: a wavetable synth with the spectrum in its hands

Vivace is a spectral warping wavetable synthesizer, a port of open-source (GPLv3) synthesis code to the Push: three wavetable oscillators that scan through up to 257 frames and bend them in the spectrum and in time, a sample source, two filters with 32 models, six envelopes, eight LFOs, a 64-slot modulation matrix and nine effects. It needs no firmware, and two Vivaces can play side by side.

It opens on its three wavetables, drawn in three dimensions as the frames recede, the frame each oscillator plays lit; beside them the filter and what modulates what. Its pages follow the synth's sections, with the envelopes, filters and LFOs drawn by Pung, so they move as the sound does. Knobs read in the synth's own units.

Sounds. Twelve factory sounds of its own come with it. Your own sound files (.vital, the format of the synth this engine comes from; the wavetables travel inside) go into the module's Presets folder; each folder becomes a bank. A sound is played with at most 16 voices and 2x oversampling.

Wavetables. Each oscillator has a Table page, right after its own. Encoder 1 picks a type (Basic, Analog, Digital, Drive & Fold, FM, Vocal, Harmonic & Organ, Keys & Plucks, Strings & Winds, Bass, Chip & Game, Spectral, Texture, Collection), encoder 2 a table of that type: 187 tables come with Vivace. Preset is the sound's own table, and From Presets offers every table your sound files carry, so a table from one sound can play in another. The other six encoders shape what you hear: frame, spectral morph and warp under the table, their modes and the warp's phase under the frame as it plays. The table is drawn as the oscillator plays it, the spectral morph and the warp applied to every frame, and the frame the sound is on lit as an LFO or an envelope sweeps it.

On the Push

The sound, live

While a device plays, its pictures show what the sound is doing, not only how it is set. They follow one rule: nothing moves unless the sound moves, and nothing moves that Pung cannot know. Where Pung cannot know something, the picture stays still rather than guess.

One colour means "the sound, right now": the cyan blue of the marks below. Orange still means the encoder under your finger, and white is how the device is set.

  • Envelopes. Every note you play is a dot running along the envelope's lines in time: up the attack, down the decay, resting at the sustain point while you hold the key, and down the release once you let go. Under the envelope, a bar of its stages (A, D, S, R, or T1 T2 T3 S T4 on a JV) lights the stage each note is in; each stage is drawn as wide as its knob is turned. When a module gives its times in milliseconds or seconds, or Pung knows its engine (Mini-JV, Dexed), the timing is exact; otherwise Pung reads the time from the knob, and for the volume envelope it also listens: the dot waits at the top until the sound actually peaks, and the next notes run on what it heard. Effects' envelopes, such as a gate's, stay still: they follow the audio, not your notes; so do looping envelopes, which run on their own. Each new note briefly lights the envelope's start.
  • Filters. Behind the curve, in grey, is the actual sound: its spectrum, low notes on the left, high on the right. When the sound reaches higher than the curve, something else is opening the filter, such as its envelope or key follow.
  • Modulation. A knob that an LFO, an envelope or the modulation matrix moves shows where the sound has it now: a cyan dot outside its ring, and an arc from where you set it. A filter's curve moves with its modulated cutoff. Vivace, Xenia, Vavra, OsTIrus, Nodal Red 2X and Surge XT report this from their engines; the screens of a module that cannot tell stay as they are set.
  • LFOs. A dot runs along the wave at the LFO's real speed when Pung can know where the LFO is: when it is synced to Live's tempo with a rate like 1/8, or restarted by each note with a rate in Hz. An LFO that restarts on each note flashes at its start when you play. Any other LFO stays still.

The pictures move while a note is held or the device sounds, for a moment after, and with Live's transport when a picture follows the tempo. The rest of the time the screen is drawn only when something changes. Most modules don't report where their envelopes and LFOs are, so for them the motion comes from the sound and the notes, and a free-running LFO stays still.

On the Push

Assigning modulation

On a front panel with segments, choose a segment and nudge the jog wheel right: Assign opens for the segment's controls. Choose a source on the lower buttons (the LFOs, the envelopes, velocity, the mod wheel, aftertouch, the macros and the rest of what the synth offers), then turn the encoder under a control: the source now moves it, as far as you turn.

  • Turn from zero to add a route, turn further to change it, turn back to zero to remove it (or hold Delete and touch the encoder).
  • A turn alone is additive: the source pushes the control one way from where you set it (+20%). Shift + turn is bipolar: it swings both ways around it (+-20%).
  • Select + turn moves the control itself, the point the routes start from.
  • The jog wheel still walks the segments, and the source stays chosen: hold LFO 1 and dial it into the oscillators, the filter and the amp in one pass. Past the last segment it goes on into More.
  • More (upper button 3): every other control a route can reach, eight at a time, by the synth's own pages. Routes (upper button 4): the chosen source's routes wherever they are; with Shift, every source's. Upper button 2 is the segment again; a nudge left goes back to it, and Exit leaves.

Above each encoder: the control, the range the source sweeps it through as a cyan arc, where the sound has it now while a note plays, and the other sources that already reach it. Switches and menus show Fixed, and so does anything the synth's own matrix cannot reach. A synth whose matrix is full takes no new route, and the screen says so.

The synth's own sources work on Vivace (64 routes, kept with the device), Xenia and Vavra (their matrices, 16 and 8 slots, kept in the sound), OsTIrus (its six assign slots; an LFO's polarity is the Virus's own bipolar or unipolar source) Nodal Red 2X (its fixed routes: each source reaches its own destinations, one at a time) and Surge XT (its routes from any of its sources, saved with the device).

Pung's own modulation, on every device

After the synth's own sources, the lower buttons hold four of Pung's, in magenta: LFO A, LFO B, Wheel (the mod wheel: a keyboard's, or Push's touch strip once you switch it to mod wheel with Select + a tap on the strip, in Push's own view) and Pressure (aftertouch: the newest held pad's or key's, back to nothing when you let go). They work on every Pung device with a front panel, including the many modules that have no modulation of their own, such as OB-Xd and Plaits, and they reach controls the synth's own matrix cannot, such as Nodal Red 2X's resonance. Assign them as above: choose one, turn an encoder.

  • The whole sound moves together. Pung moves the control itself, for every voice at once, like a global LFO; the synth's own sources stay per voice. On the emulated synths a fast sweep moves in small steps, as from a hardware controller.
  • The knob stays where you set it. Pung's view, the web page, Live, automation and saved sounds all see your setting; the dot beside the ring shows where the modulation has the sound now. Turning the knob, automating it or loading a sound moves the centre, and the modulation goes on around it. Remove the last route and the control is back at your setting.
  • An LFO's settings: press the chosen LFO's button again. Sync (Free, or 1/32 to 4 bars on Live's tempo), Rate (0.02 to 30 Hz) and Shape (sine, triangle, saw, square, random), with the wave drawn as it runs. Press again to go back. On an emulated synth (Nodal Red 2X, OsTIrus, Vavra, Xenia) a sweep stays smooth to about 4 Hz: the synth takes about 50 changes a second, so faster ones step, and the settings say so. Its own LFOs are smoother up there.
  • Levels, not choices. On/off switches, modes, octave and voice counts, preset numbers and MIDI settings show Fixed for Pung's sources; turning one says why.
  • Kept with the device in your Live Set, so a route stays when you change the sound.

On the Push

Pung and Push's own view

Push's own device view edits every Pung device too: its Bank N is the module's own page N. The Pung view takes its place whenever a Pung device is selected and Push shows its device view.

  • Move to a track with a Pung device and the Pung view stays. Move to any other track and Push's own view is back.
  • Press Device in the Pung view to see the same device in Push's own device view (its Bank pages). Press Device again to return to the Pung view. This holds only while you stay on that device: select it again later and the Pung view opens as usual.
  • To keep Push's device view for good, switch Pung's DEVICE off in Push Hack Home (Shift + Help, choose PUNG, lower button 3), or on push-manager's Display page.
  • From Push Hack Home you can also open Pung by hand, on any track.

Playing

MIDI effects

Live on Push has no slot for a MIDI-effect plugin from another maker, so Pung's MIDI effects (the arpeggiators, chord tools and sequencers) reach a sound in two ways.

  • Inside a Pung instrument. Every Pung instrument has a MIDI FX selector on the pages after its own, one page per MIDI effect with that effect's settings. Pick one and it plays in front of the synth.
  • On a track of its own. Load a MIDI effect from User Library › Presets › Instruments › Pung MIDI Effects on its own track. On the track it should play, set Live's MIDI From to that track and the effect. This drives any instrument, Live's own included.

Beside the Push

The web page

Open http://push.local:7720 on a computer, tablet or phone on the same network (Push Hack Catalog may give Pung another port; push-manager's page lists it).

  • Devices: every Pung device in the Set, by track. A device's sections are the same as its pages on the Push, under the same names. Change a value on either side and the other follows within half a second; click a section's title and the Push turns to it.
  • Sound: the device's sounds, as in the sound browser on the Push: Factory, User, Favourites and Recent, the bank, and a search over every name. Click a sound or use the arrow keys to hear it, Enter or a double click keeps it, Esc brings back the sound you had. Each sound has a star, and yours can be renamed and deleted. Export downloads your sounds as Schwung preset files; Import adds such files, from another Push or from a Move.
  • Samples and files: a device that plays a sample shows it with its waveform; click it for the same file browser as on the Push, with three things added. Search finds a file by words in its name or folder. Listen here, or a click in the waveform, plays the file on this computer. And you can drop files from your computer onto the list: they go into the folder shown, inside your User Library, and are on the Push at once.
  • Sounds (top of the page): your sounds for every module in one place, with a search over all of them; star, rename, delete, and Load on any Pung device in your Set running that module. Export all is one zip in the folder layout a Move keeps; Import sorts every sound of such a zip into its module.
  • Compartment pills: the device's sections as pills above its panel. Click one to show or hide its section, double-click one to show only that one, All to show every one. With one on, the Push turns to it; a dot marks the one the Push shows.
  • A module's own panel: modules with a web panel of their own (JE-8086, Mini-JV) show it there; the pills show and hide its sections too where the module supports it (Mini-JV).
  • Live: the sections' pictures move as they do on the Push (see The sound, live), and Mini-JV's panel shows its voices under the Macros. Only the sections you show are updated, and nothing is sent while the page is in a background tab.
  • Settings: Push display › Detail card on touch brings back Move's large card on every touch. It is off on the Push, where the touched cell already shows everything in place.

Beside the Push

Adding modules

The Modules page on Pung's web page lists every module that came with your Pung release: instruments, audio effects and MIDI effects, by kind and tag, each with its version, licence and source. A module with an interface of its own on the Push shows its front panel on its card; its sheet has every screen of its own to step through (the arrow keys work), and Custom interface lists them all. An emulator's pictures show it at rest, as Pung draws it before your firmware brings its sounds.

  1. Install the modules you want. They install from the copy inside Pung's release, on the Push itself: nothing is downloaded.

  2. Apply. New devices need one Live restart, because Live looks for plugins only when it starts. Apply saves nothing for you: save your Set first. Live restarts in about 30 seconds and recovers the Set. Install several modules, then Apply once.

  3. Add firmware where a module needs it. JE-8086, Mini-JV, Osirus, Nodal Red 2X, OsTIrus, Vavra and Xenia emulate hardware and need its firmware, which Pung never ships. Add the file on the module's card; Pung recognises it by its checksum (OsTIrus's by its size).

Emulators rest in silence. An emulated synth works as hard silent as playing: Nodal Red 2X takes almost two of the Push's four processor cores, OsTIrus one, Xenia and Vavra most of one. So Pung lets each one rest: ten seconds after its sound has died away, with no key held, it stops working and takes nothing, and the page on Pung's web page says Resting beside it. The next note, knob or sound wakes it, and that first note is as on time as any other. JE-8086 and Osirus rest the same way. A Set with emulators in it leaves the Push's processor, and its battery, alone while you are not playing them. A module's card says what it takes while it plays.

Room for an emulator. Two emulators run at once, and an emulator starts only while the Push can carry it beside what already plays. One that would not fit waits, silent, and starts by itself when there is room.

A new Pung release brings new modules and new versions; the Modules page shows them (see Updating). Removing a module needs Apply too.

During the test phase, modules come inside Pung's releases. After it, Pung's module pipeline, which is already built, will serve them directly, so updates arrive as Schwung publishes them.

Help

Removing Pung

Remove Pung with Push Hack Catalog. Its browser entries go with it. Its plugin stays on purpose, so Sets that use Pung devices still open, with those devices silent.

Delete the plugin (/data/.vst3/Pung.vst3) only when no Set uses it any more, and never just before Live recovers from a crash: Live replays the Set's history while it recovers, and a missing plugin crashes it.
