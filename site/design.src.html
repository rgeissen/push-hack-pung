Design · For module authors and contributors

Bringing a Schwung module to Push.

A Schwung module was designed for Move: one small screen, one parameter at a time. On Push it gets eight encoders with a 120-pixel column each, a 960 × 160 colour screen and a web page beside it. These are the principles that turn one into the other: Push native, Pung default and Pung custom, with the modules that show them.

Foundation

One instrument, two surfaces

A module has one structure, cut into compartments: one compartment is one screen on the Push and one section of the web page. The Push and the web page are two views of that one structure, and each does what the other cannot. The Push shows one compartment at a time, under the hands: eyes on the music. The web page shows every compartment at once: overview and precise entry.

  1. Same names, same order. A compartment, page or parameter has one name on both surfaces. The Push writes it in capitals; that is the only difference.

  2. Same pictures. A structure Pung recognises is drawn from one rule set, in Go for the Push and in JavaScript for the web. A change to one is a change to both; a test checks that both find the same pictures on all 827 pages of the 100 captured modules.

  3. Same motion. One live session per sound feeds the Push and every web page watching it, so the two can never tell different stories about what the sound is doing.

  4. Same state. A value turned on the Push moves on the page within half a second, and the other way round. Clicking a section's title turns the Push to it.

  5. Same touch. What is under a finger on the Push is drawn hot; on the page, what is under the pointer or keyboard focus is drawn hot the same way.

  6. A module's own web panel follows the compartments too, in the same order and under the same names.

Foundation

Three levels

Every Pung device has up to three interfaces on the Push, each further from Push's own look. Most modules should never need the third. The default must be world class on its own, because it is what nearly every module shows.

1 · Push native

Push's own device view

Live's parameter banks, names and value strings. Always there, for every module, and the fallback. Push's Bank N is the module's own page N.

2 · Pung default

Designed from the parameters

Knob cells, lists, the header and the track row, built from the module's own sections. Pung draws the structures it recognises, and a module can add widgets over its knobs.

3 · Pung custom

The module's own screens

A page screen, a band screen or a full takeover, only where it is substantially better than level 2 and true to the instrument.

The canvas

The screen

960 × 160 pixels in four bands, and eight columns of 120 pixels, one per encoder. A picture covering columns 3 to 6 is about encoders 3 to 6: place things over the knob that changes them. A custom screen may break the columns; the name and value row below it never does.

Each was a guess at what Push does. Pressing through Push's own view, and reading the lights it sets, replaced the guesses.
  • Pung's own additions sit where Push has nothing: in an open device, upper button 8 (SOUNDS) and a jog press open the sounds, on the buttons where Push puts a device's own actions; Save saves the sound; Page steps pages (Push leaves it unused in its device view).
  • Never take a button that does more in Push. Swap looked like the natural home for a sound browser, but Push's Swap is Hot-Swap, which can replace the device itself. Taking it would have removed the way to swap one Pung device for another. Add and Swap stay Push's.
  • Live's buttons stay Live's. Mute, Solo and Delete are read, never taken: the pads need them. Push takes a Mute let go within about 0.4 s as a tap on the selected track, so when the press was used with one of Pung's buttons, Pung puts that track back.
  • Not there yet: a page's switches on the upper buttons of an open device, automation dots, and moving a device by holding its button.

The canvas

Colour

The panel has 16-bit colour and no transparency: gradients show steps, and a translucent fill does not exist. To fade a colour, mix it toward black. Colours are named by meaning, never by look.

slotthis device's identity: what is touched or edited now
fgvalues, lines, the shape itself
dimnames, labels, secondary text
linebaselines, separators
faintcolumn rules, empty areas
modthe sound, now: playheads, the notes' gate, live voices; and modulation
warnerrors only

Three meanings, never mixed. fg is how the device is set; slot colour is your hand; mod colour is the sound as it plays. A live mark is never in slot colour, so motion is never mistaken for a touch.

Slot colour is precious. It means "this is yours, now". Use it for the touched element and the selection, and for fills mixed 28% toward black. Never use it for decoration. Each device's slot colour comes from Push's palette:

The canvas

Type and text

  • Two faces. Labels in Tamzen capitals, 7 px a character. Values in the value face, 16 px. Text is ASCII.
  • Lines are 2 to 2.2 px at rest and 3.5 px when touched. Handles are 3 px dots at rest, 4.5 px when touched. Fills are flat, under their line. Guides are 1 px, dashed or dim.
  • Room is short: truncate a name, never a value.
  • Fit text by measuring it, never by counting letters. A label is cut and ends in .. A value moves to a smaller value face first and is cut only where that does not hold it either.
  • A number is never cut. -240. reads as another number. It is shortened, -24000 to -24K, or not shown. Both ends of a range shorten together.
  • Neighbouring columns keep 16 px between their texts, so a row of values reads as columns.
Counted
TXRX PROG CHAN.Bank Sel + ProgRANGE -240. 24000

Eleven letters fitted by count cross the box in a proportional face, and a cut number lies.

Measured
TXRX PROG CHAN.Bank Sel + Pr.RANGE -24K 24K

A smaller face, cut only at the end; the range shortened, both ends alike.

The header

Laid out from the right, each part only where it fits whole, never crossing the device row. The page indicator gets its room first: it says where the jog wheel and Page go. Then the level meter: at rest a floor line, not ten dim blocks that read as an indicator that does not work. Then a warning, whole or not at all; then COMPARTMENT / PAGE; then the track.

Level 2

Pung default

Pages come from the module

In this order of preference: the module's own compartments in its push_ui.js; else its ui_hierarchy, the sections Move's browser shows; else its keys grouped by what their names say (amp_*, filter_*, lfo1_*), never splitting a group that fits a page. Every parameter has a page, and numbered pages (PAGE 1..24) are a failure: a page's name says what is on it.

Pictures for structures Pung knows

Where a page's keys describe a structure Pung knows, Pung draws it over those knobs, for any module. The names come from what 100 modules actually publish:

  • Envelope: adjacent keys with one shared prefix naming its stages: by word (attack or atk, decay or dec, hold, sustain, release, delay), with a unit after it (amp_attack_ms), by letter (fenv_a), or numbered after an env or eg prefix: Roland's time1..4 and level1..4, Yamaha's r1..4 and l1..4, whole on the page.
  • Filter: a cutoff (cutoff, cutofffrequency, or freq after a filter's name) beside its resonance (resonance, reso, res, q) or its type. A type that names a filter gives the response (low-pass, high-pass, band-pass, notch) and its slope from its name (LP 24 dB, Analog 4P). A type Pung cannot read draws no curve, only its name.
  • LFO: a wave (shape, wave, form) beside its rate, under a name with lfo in it: one to five cycles as the rate knob goes. A wave Pung does not know exactly is drawn as its name.
  • Mix: three or more adjacent levels of different sources, named alike (saw_level, pulse_level, sub_level): a fader over each, and each source's share of the whole. Never an envelope's levels or an FM operator's.

  • Draw only what is true. An attack and a release alone are a compressor's timing, not an envelope. A picture that lies is worse than knobs.
  • Draw in the knob's terms. Times in proportion to their knob, not in milliseconds: the shape is what the hand turns.
  • A module's own widget wins over Pung's picture for the same columns.
  • What the fleet gets: across the 100 captured modules, 34 pages draw a filter, 29 an LFO, 10 a mixer and 124 an envelope (35 modules); a test pins the list, so a rule's change shows module by module.

Level 2 · Behaviour

Live pictures

The rule

While a device plays, its pictures show what its sound is doing. Nothing moves unless the sound moves, and nothing moves that Pung cannot measure or know. A movement comes from one of four sources: measured from the sound, exact from the notes or Live's transport, exact from a unit the module states, or read from the instrument itself. Where none of them knows, the picture stays still. No motion is decoration, and none is a guess.

  • The look. A playhead is a mod dot ringed in black, with a dashed hairline to the base. Its trail is its last nine positions, fading toward black. Nothing eases or bounces: the sound does not. The spectrum is neutral grey laid under the curve that shapes it, never over it, falling at most 36 dB a second.

  • Time it, or measure it. Of 307 envelope time knobs in 100 modules, 54 state a unit and 95 have a range in seconds; of the other 158, Dexed's get msfa's own times from its overlay, and the rest run on Pung's curve, which the amplitude envelope's sound corrects. A module that states its times in ms or s gets exact dots for nothing. Where an instrument's times have no unit at all, measure them once off the instrument, as Mini-JV's were, or run its engine's own maths, as Dexed's overlay does, and give them to Pung with push.envelopeTimes.

Behaviour

Moving between devices

Live decides which device is shown; Pung and Push hand the screen to each other as the selection moves. What the user sees must always be one device, whole. Each rule below comes from a fault measured on the device.

  • A frame never mixes two devices. A device is drawn once Live has resolved it and its own parameters are read; until then the last frame stays.
  • A device seen before is drawn at once, from what it was left as, while Live confirms it behind the frame.
  • A knob writes only to the device shown, and only once Live has confirmed it. A turn during a switch is dropped, never sent to the new device with the old one's parameter.
  • Each device keeps its page, as on Push.
  • A knob writes only to its own parameter. Live's parameters are matched to the module's by position in the device's list, and checked by name. Names alone are not enough: a JV-880's four tones share them, and a knob on one tone could change another.
  • Leaving for a device that is not Pung's, Pung goes quiet at once: no frame, no light, until Push has the screen back.

Level 3

Pung custom

The bar

A custom screen ships only if it is substantially better than the default and true to the instrument. It earns its place by showing what knobs side by side cannot: relationships (a signal path, two curves on one axis), the whole at once, or the instrument's own vocabulary (its section names, its display, its way of describing itself). If it only restyles the default page, it does not ship. Write one sentence saying what it shows that the default cannot; without that sentence, leave it out.

Three sizes

A page screen draws the band for one page: a DX7 operator's keyboard level scaling over a keyboard. A band screen draws the band for every page of a compartment: Osirus's filter routing. A takeover draws the whole panel, and Pung draws none of its own elements.

  1. Reuse Pung's pictures for the structures Pung knows (g.envelope, g.filter, g.lfo, g.mix, not hand-drawn ones). The user has learned those pictures on every other module.

  2. Move only with the sound. Draw motion from v.$live (the notes, the level, the transport) or from your module's own state (live_keys), never as decoration, and in mod colour.

  3. Respect the bands. Draw in yours (952 × 86); the header and the name and value row belong to Pung.

  4. Show the touch. Whatever is under a finger (v.$touched) is drawn in slot colour.

  5. Show unknown honestly. Check v[key].known and draw a neutral shape until values arrive.

  6. Fit the budget: 8 ms a frame, 14 ms for a takeover. One g.poly per curve; cache what does not change.

  7. A takeover owns the jobs it replaces: every encoder's name and value (v.$knobs), the touched one, and which page of how many. The bottom 56 pixels are the encoder row, so the hands find their values where they always are.

  8. Never draw an envelope yourself. Every envelope is Pung's: one model (a start, its stages, one plateau, its release), each segment as wide as its knob has turned, each note a dot on its own clock, one stage bar. What only a module knows is how long its stages take; it says that with push.envelopeTimes, and Pung draws the rest. Mini-JV and Dexed are drawn this way.

  9. The web side. A custom screen's compartment is a section of the web page with the same name, and Pung's page shows the same screen, drawn by the same code.

  10. A way back, always. A takeover shows only while its device is open, and Push's way back (upper button 1, a jog nudge left) and the page row are drawn over it on opening, on a page turn and while the jog wheel is touched. Any failure returns to the default view.

The code

A module declares its compartments in push_ui.js beside its module.json (Move ignores the file), or Pung ships an overlay for it. A screen draws with a small API; nothing it draws can leave its frame.

push.compartment({
  id: "filter", label: "Filters",
  pages: [
    { label: "Filter 1", keys: ["cutoff", "filter1_resonance", "filter1_mode"] },
    { label: "Routing",  keys: ["filter_routing", "saturation_curve"] },
    { label: "Envelope", keys: ["f_attack", "f_decay", "f_sustain", "f_release"] }
  ],
  // optional: draw the band (952 x 86) on every page of this compartment,
  // with the values of all its keys in v
  screen: function (g, v, t) {
    g.text(8, 14, "FILTER 1", v.$touched === "cutoff" ? "slot" : "dim", -1);
    g.envelope(8, 20, 300, 60, { attack: "f_attack", decay: "f_decay",
                                  sustain: "f_sustain", release: "f_release" });
    g.value(320, 50, v.cutoff.display, "fg", -1, 120);   // fitted to 120 px
  }
});

Osirus · the Virus's filter routing

Both filters as a signal path, serial, parallel or split, with the saturation stage between them and both responses on one axis. Its seven compartments are the sections of its own web page; two of them draw band screens, because there a picture shows a relationship the knobs cannot.

Every other module

OB-Xd and Braids add their own widgets over their knobs, inside the default view; their envelopes are Pung's own (g.envelope), so they play live like every other. Hera's widgets show the wave its Juno-style DCO actually puts out (saw, pulse at its width, the sub an octave down, noise as a band), how far PWM moves the pulse, and where the envelope takes the cutoff. The rest show the default view alone: their own sections as pages, and Pung's envelope, filter, LFO and mixer wherever one is recognised, all playing live. That is the point of the default: 102 modules, each one usable and readable on the Push from day one.

Beside the Push

The web page

  • Pung's page draws the default. Each compartment is a section; a custom screen's compartment is headed by that screen, refreshed with the values. Click it to turn the Push to it.
  • Pictures are direct. An envelope's handles can be dragged: a stage's corner sideways sets its time, up or down its level (the plateau's: the sustain). A filter's cutoff handle drags sideways, and up or down for its resonance; a mixer's faders drag up and down. The slider below moves with it, and the Push follows.
  • Pictures play here too. The page streams the sound's live frames and draws the same dots, stage bars and spectra as the Push. An envelope's frame carries each note's clock rather than its position, and the page runs that clock on every animation frame, so its dots move as smoothly as the screen. It asks only for the sections it shows, and nothing while it is hidden; a frame it cannot take in time is dropped, never queued.
  • The keyboard path is the controls. Every value has a slider or a menu, reachable with Tab. A picture is never the only way to a value, and carries a label naming its values.
  • Phone widths. Cards stack, a picture keeps its proportion, a row of controls folds to two columns.
  • A module's own panel runs in a sandbox under a strip of its compartments, gets the values Schwung's own manager sends, and follows the same rules. While it shows, it also gets every live frame as {type: "live", frame}: Mini-JV's panel draws its voices from it.

Behaviour

Motion and budget

  • Things move only when the instrument moves, from what can be measured or known (see Live pictures). A static value is drawn still.
  • A widget or a screen gets 8 ms a frame, a takeover 14 ms. Three slow frames in a row, or one over 40 ms, switch it off until Pung restarts; the default view comes back and the header says why.
  • Measured on the device: JE-8086's Patch takeover draws in 3 to 5 ms, Mini-JV's Macros in about 3 ms (about 4.4 ms with its live voices). A page of plain knobs draws in about 7.4 ms in all; the live spectrum adds about 1 ms, a playhead nothing measurable. Pung's own pictures are drawn in Go, outside a module's budget, and a web render never counts against the Push's. What each frame costs is always reported in /api/surface/state.

Before it ships

Review checklist

  • Names and order match on the Push and the web page.
  • It is a compartment, or lives inside one; its title on the web turns the Push to it.
  • Pung's pictures are used for the structures Pung knows.
  • The touched element is in slot colour, and slot colour is used for nothing else.
  • Unknown values draw a neutral shape, never a guess.
  • Motion comes from the sound or the instrument (v.$live, live_keys), in mod colour; where nothing knows, the picture stays still.
  • Every value is readable as text somewhere on the screen; the row under a picture counts.
  • Nothing covers a knob that is not being turned: no card, no notice the header already gives.
  • Nothing is drawn outside its band; the header and the name and value row are untouched.
  • Every text is fitted to its room by measuring it, and no number is cut.
  • It stays under 8 ms a frame on the device (14 ms for a takeover), measured there.
  • For a custom screen: one sentence saying what it shows that the default cannot.
  • For a takeover: the encoder row, the touched encoder and the page are on it.
  • Where the module has a web panel: the compartments are its panels, in its order, under its names.
